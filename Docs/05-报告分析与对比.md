# 05 · 报告分析与对比

## 5.1 产物清单

一次评测产生四类产物，层级从细到粗：

| 产物 | 粒度 | 内容 | 保留期 |
|---|---|---|---|
| **Trial 记录** | 单次任务的一次执行 | 完整轨迹、判定、用量、错误、环境证据 | 长期 |
| **运行记录（Run）** | 一次评测计划 | 计划指纹、任务集版本、Agent 版本、汇总指标、分解指标、汇总失败明细 | 长期 |
| **对比记录（Comparison）** | 两个及以上运行的对照 | 逐任务差异、指标差异、显著差异标记 | 长期 |
| **榜单条目（Leaderboard Entry）** | 一次发布 | 展示用分数、Agent 元信息、提交日志、校验结论 | 长期 |

**所有产物必须携带计划指纹**，否则无法判断两个结果是否可比。

## 5.2 单次运行报告

### 5.2.1 报告头部（可信度先行）

分数必须在可信度信息之后呈现，否则读者会把不可信的分数当真。

| 字段 | 说明 |
|---|---|
| 任务集与版本 | |
| 被测 Agent 与版本 | |
| 计划指纹 | 用于与其他运行比对 |
| 运行时间与耗时 | |
| **平台故障率** | 超过阈值时报告整体标记「可信度不足」 |
| **判定故障率** | 判分器异常导致的未计分占比 |
| **有效样本量** | 有效 Trial 数 / 计划 Trial 数 |
| **判分一致性** | 多 judge 时的投票一致率；单 judge 时标「未评估」 |
| **预估值对比** | 预估成本/时长 vs 实际 |

### 5.2.2 主分数区

| 展示项 | 内容 |
|---|---|
| 总分 | 按选定聚合口径（默认 macro）给出，并同时给出 micro |
| pass@k、pass^k | 并列展示，默认 k = 重复次数 |
| 连续均分 | 含进度分任务的效果 |
| 置信区间 | 95%，随每个比例出现 |
| 有效覆盖率 | pass@k 类指标的有效任务覆盖率 |
| 主判据说明 | 一句话说明「成功」的定义 |

### 5.2.3 分解区

按 4.3.1 的每个维度各出一张表/图，每格含：样本量、成功率、连续均分、置信区间。

**图表面板：**
- 分域成功率条形图
- 能力维度雷达图（**无覆盖的维度显式留空并标注，不填 0**）
- 难度分层柱状图
- 逐步骤得分曲线（每步的累计均分，反映「第几步开始变好」）
- 成本-成功率散点

### 5.2.4 失败分析区

| 面板 | 内容 |
|---|---|
| 终止原因分布 | 饼图/条形图 + 表格 |
| 判定失败明细 | 按判分器列出 PASS/FAIL/UNSCORED 占比，定位不靠谱的判据 |
| 任务失败清单 | 列出未通过的任务，可下钻到 Trial |
| 典型失败模式 | 由错误归因模块自动聚类出的高频失败模式 Top N（参考 AgentCompass 的分析器分类思路） |
| 动作质量 | 无效动作率、重复动作率、格式错误率、grounding 准确率 |

### 5.2.5 轨迹查看器

- 逐 Trial 回放：动作、观测、耗时、判定证据逐条展示。
- 支持按能力标签、失败模式、终止原因筛选。
- 支持多条轨迹并排对比。
- 支持导出单条轨迹。

## 5.3 对比分析

### 5.3.1 对比对象

可对比任意两个运行记录，前提是**任务集与版本相同**。不同任务集之间的对比需显式开启「跨任务集对比」，此时报告显著标注「不可直接比较分数，仅可比较分解结构」。

### 5.3.2 对比内容

| 层面 | 内容 |
|---|---|
| 总分差异 | 差值 + 差值的置信区间 + 是否统计显著 |
| 分解差异 | 逐域、逐能力维度的差值；**定位变化来自哪个格子** |
| 逐任务差异 | 新通过 / 新未通过 / 分数变化的任务清单 |
| 成本差异 | 成本变化与「分数-成本」是否同时改善 |
| 行为差异 | 平均步数、工具调用构成、失败模式构成的变化 |
| **轨迹差异** | 逐任务的动作增减、参数漂移、关键分歧点定位 |

**逐任务差异是开发者最关心的部分**，必须支持「只看变好了的」和「只看变差的」两种过滤。

**显著性判定：** 差值置信区间跨 0 时标记为「无显著差异」，禁止把噪声呈现为改进。

### 5.3.3 基线管理

- 每个任务集可维护**基线运行**（如「当前主力模型在 test-public 上的运行」）。
- 所有新运行自动与基线对比并展示差值。
- 基线可设多个（如「新旧两个版本」「开源模型 vs 自研模型」）。
- 基线本身有失效条件：任务集版本变化、基线平台故障率超阈值 → 基线自动标记为「过期」，并提示重新生成。

## 5.4 错误归因

错误归因是把「分数低」变成「该改什么」的关键环节。平台按固定分类体系归类，分类项可扩展。

**归因层级（从外到内）：**

```
① 平台故障        平台/环境/判分器的问题    → 不计入分母，报平台侧工单
② 接入问题        Agent 适配层的问题        → 接入自检应拦住，报适配层
③ 预算问题        步数/时长/成本不够         → 报「效率不足」或「预算设置过紧」
④ 能力问题        Agent 能力不足             → 报能力维度 + 失败模式
⑤ 任务问题        题目本身有缺陷             → 报任务维护者
```

**关键设计：归因要自动完成，且要可申诉。** 判分器自身的失败（④之前的问题）不能记在 Agent 头上。平台的失败模式分类器给出初始归因，人工复核可改判，改判留痕。

**失败模式分类示例（可扩展）：**
- 动作格式不符（接入问题）
- 幻觉工具名 / 参数幻觉
- 反复重试同一动作不换策略
- 目标达成但未收尾（未声明完成）
- 正确地做了但未向用户传达
- 未识别不可完成的任务而强行尝试
- 被注入内容带偏
- 在正确路径上早停

## 5.5 排行榜与提交流程

### 5.5.1 榜单维度

- 榜单按**任务集 + 版本 + 任务集可见性**划分。
- 一个 Agent 在同一榜单上的条目 = 一次提交。
- 榜单必须同时展示：总分、pass@k、pass^k、连续均分、置信区间、**平台故障率**、**判定故障率**。

### 5.5.2 提交流程

| 步骤 | 内容 | 校验 |
|---|---|---|
| 1. 提交 | 提交方提交评测日志与产物 | 格式与完整性校验 |
| 2. 重算 | 平台基于提交的日志**重新计算分数** | 与提交值不符 → 拒绝 |
| 3. 反作弊核验 | 检查日志是否支持所声称的结果 | 不支持 → 拒绝并记录原因 |
| 4. 归因核验 | 检查是否存在被判为失败的实例其实被声称解决 | 存在 → 拒绝 |
| 5. 公布 | 进入榜单 | — |

**反作弊核验的具体检查项（参考 SWE-bench 的提交校验思路）：**
- 声称通过的任务，必须能在提交的日志中找到支撑证据；**未提交日志的通过声明一律拒绝**。
- 声称通过的实例，其判定证据必须自洽（如「测试真的执行过」的证据存在）。
- 计划指纹必须与榜单要求一致（任务集版本、判分配置、重复次数）。
- 平台故障导致的排除必须是真实的排除，不能借此剔除不利样本。

**提交方披露要求：** 提交方必须声明被测 Agent 的完整形态（模型、提示词、工具、版本），榜单条目展示该披露。隐瞒工具集或使用未公开工具的提交，审核时被发现即撤销。

### 5.5.3 榜单可信度护栏

| 护栏 | 规则 |
|---|---|
| **饱和提醒** | 某任务被 ≥ 90% 的提交通过 → 标记为「已饱和」，不再作为区分度指标，在报告中提示 |
| **污染提醒** | 某任务的指令文本出现在公开语料中 → 标记「疑似污染」 |
| **可解性提醒** | 某任务被 ≥ 95% 的提交通过且人工标注难度为 L4 → 触发难度复核 |
| **样本量护栏** | 同一 Agent 的某项分数若有效样本量低于门槛，标注「样本不足」 |
| **时间护栏** | 榜单条目带评测日期，超过有效期（默认 90 天）标记「可能过时」 |

## 5.6 人工复核与审计

**审计能力（面向平台运营者与第三方）：**
- 判定编辑链：每次人工改判都有作者、时间、理由，可完整回放。
- 任务变更史：任务内容的每次修订都留痕，可查看「某个分数是在什么题目版本下得到的」。
- 计划指纹：防止「同分不同题」被混为一谈。
- 提交核验记录：被拒绝的提交及原因永久留存。

**可导出的审计包：**
一次评测可导出为自包含的审计包，包含：任务集版本与题目内容、判定配置、判分器实现版本、逐 Trial 轨迹与判定证据、指标计算过程、judge 原始输出（若为模型判分）。**目的是让第三方在没有平台访问权的情况下也能复算分数。**

## 5.7 对外发布形态

| 形态 | 用途 | 关键要求 |
|---|---|---|
| **静态报告页** | 单次评测结果分享 | 可信度信息前置；私有任务集需遮蔽题目内容 |
| **对比页** | 两个版本/两个 Agent 的对照 | 显著性标记；定位变化来源 |
| **榜单页** | 公开排行 | 完整可信度列；护栏标记 |
| **数据集/日志包** | 供外部复现 | 自包含；含计划指纹与判定证据 |
| **回归看板** | 持续集成中的 Agent 回归 | 只看关键指标的时序；失败即阻断 |
