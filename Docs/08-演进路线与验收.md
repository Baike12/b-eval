# 08 · 演进路线与验收

## 8.1 阶段划分

路线按**「先能跑通，再能信任，最后能运营」**推进。每一阶段以可验收的功能闭环结束，不做半成品堆叠。

### M0 · 骨架与接入打通

**目标：** 一个 Agent 能在平台上跑完一个任务并拿到分数。

| 交付 | 验收标准 |
|---|---|
| 被测对象注册与接入适配 | 一个改造量最小的 Agent 完成接入，用时 ≤ 1 天 |
| 接入自检 | 自检能报出动作格式错误、契约违规；自检不通过时评测功能被禁用 |
| 最小任务模型 | 支持「指令 + 初始状态 + 动作空间 + 判定条件 + 预算」五要素 |
| 两类判分器（状态校验、规则判据） | 至少 10 道样例题，判定结果与人工判定 100% 一致 |
| 单次运行与轨迹 | 轨迹完整记录动作/观测/用量/终止信息，可回放 |
| 基础指标 | SR、pass@k、pass^k、avg@k 计算正确（对已知答案用例做断言） |

**不包含：** 任务集管理、报告分解、榜单。

### M1 · 任务体系与判分体系成型

**目标：** 任务可被系统化管理，判分能力可复用。

| 交付 | 验收标准 |
|---|---|
| 任务 CRUD + 能力/域/难度标注 | 标签互斥检查生效；难度四档定义落地 |
| 任务集版本管理与冻结 | 发布后修改被阻断；版本 diff 可查 |
| 六类判分器全部可用 | 每类至少 2 个真实判分器实现；每类都有「已知通过/已知失败」回归样本 |
| 判分器注册与组合 | 支持合取/析取/权重/部分给分；部分给分的分数与判据逐项对应可查 |
| 任务入库校验闸门 | 八项校验全部实现；任一项失败能阻断入库并给出修复指引 |
| 环境隔离与四阶段生命周期 | 两个并行 Trial 互不污染；清理后无残留资源 |
| 判分不可见 | 判分条件在 Agent 可访问范围内检索不到；入库扫描能拦截泄露的题 |
| 引入外部基准 ≥ 2 个 | 至少导入 SWE-bench 与 τ²-bench 子集，完成映射并重跑基线 |

### M2 · 执行编排与报告分析

**目标：** 跑得稳、看得懂、能对比。

| 交付 | 验收标准 |
|---|---|
| 评测计划与成本预估 | 预估的 token/费用/时长与实际偏差 ≤ 30%（同任务集历史数据充分时） |
| 并发与自适应限流 | 服务端限流时能自动降速，恢复后能自动提速；无请求风暴 |
| 预算熔断 | 六类预算均生效，触发后 Trial 正确终止并标记终止理由 |
| 失败分类 | 六类失败分类准确；平台故障不计入分母，且在报告单列 |
| 断点续跑 | 中断后续跑，结果与一次跑完一致（指标一致率 ≥ 99%） |
| 离线重打分 | 换判分器重判历史轨迹成功；原判定保留且可对比 |
| 单次运行报告 | 可信度区前置；分解区覆盖域/能力/难度/划分；失败分析含终止原因与判分器明细 |
| 对比分析 | 总分/分解/逐任务/成本/行为/轨迹六层差异；显著性标记正确（差值置信区间跨 0 时不标改进） |
| 基线管理 | 基线自动对比；基线过期自动标记 |

### M3 · 质量保障与安全评测

**目标：** 分数可信，能防作弊，能做攻防。

| 交付 | 验收标准 |
|---|---|
| 判分器回归与版本绑定 | 判分器改动未过回归集时阻断发布；报告展示判分器版本 |
| 题目健康度审计 | 五项审计可定时运行并产出告警；告警可进入整改流程 |
| 人工复核工作台 | 改判留痕完整（作者/时间/理由）；历史不可删 |
| 复核抽样与偏差率 | 强制复核项自动进入队列；自动判分偏差率可计算 |
| Judge 校准 | 人工标注集建立；一致率低于阈值的 judge 被禁止用于正式评测 |
| 攻防评测 | 攻击库/防御库/注入点自动发现可用；双轴报告产出；攻防权衡曲线正确 |
| 外部请求管控 | 白名单、拦截、不可逆动作管控、频率上限生效 |
| 平台健康度 | 六项指标与阈值行为生效；故障率超阈值时报告标记「可信度不足」且不参与榜单 |

### M4 · 榜单与运营

**目标：** 可对外发布、可被第三方审计。

| 交付 | 验收标准 |
|---|---|
| 榜单发布 | 按任务集与版本划分；榜单条目展示完整可信度列 |
| 提交流程 | 平台重算分数；重算值与提交值不符时拒绝 |
| 反作弊核验 | 三类核验（证据支撑、判定自洽、指纹一致）全部实现；未提交日志的通过声明被拒绝 |
| 披露要求 | Agent 形态披露缺失的提交被拦截 |
| 榜单护栏 | 饱和、污染、样本量、时效四项护栏生效 |
| 审计包导出 | 自包含审计包可被第三方复算出相同分数 |
| 权限模型落地 | 改判权与提交权分离生效 |

## 8.2 跨阶段的持续性验收项

以下项在每个阶段结束时都必须通过，作为阶段验收的一部分：

| 项 | 标准 |
|---|---|
| **基准回归套件** | 平台自带最小集 + 判分器回归集 + 指标已知答案用例，100% 通过 |
| **归因正确性抽查** | 随机抽 20 条失败 Trial，平台归因与人工归因一致率 ≥ 85% |
| **分数可下钻** | 报告中每个汇总数字都能定位到构成它的 Trial |
| **不可信数字显式** | 所有被排除/NA/无覆盖的数值在界面与导出中均与正常值区分 |
| **接入无回归** | 已有被测对象在新版本上不需修改即可继续评测 |

## 8.3 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| **判分不可见与公开榜单冲突** | 第三方提交方能看到判分逻辑 → 刷分 | 见 Q3。优先方案：对外榜单只用私有任务集的判分，公开集只用于自评 |
| **judge 噪声** | 模型判分引入的误差超过被测差异 | Judge 校准 + 置信区间 + 强制「结论必须附证据」；关键结论要求人工抽检 |
| **任务生产成本** | 高质量任务集建设周期长 | 任务模板化 + 外部基准导入 + 社区提交 + 入库闸门保证质量而非数量 |
| **接入协议过于宽松** | 各种 Agent 行为不可比 | 协议只定边界（动作/观测/终止/用量），可比性靠「契约 + 预算口径统一」保证，靠报告标注各 Agent 的偏离 |
| **平台故障污染分数** | 分数不可信 | 故障不计入分母 + 故障率超阈值否决报告 + 平台健康度公开 |
| **任务泄漏到训练集** | 分数虚高 | 私有任务集 + 污染探针 + canary + 定期轮换 |
| **判分器被针对性优化** | 测不准真实能力 | 判分器回归集 + 判分器版本随分数落盘 + 定期更换判分实现 |
| **评测成本失控** | 项目不可持续 | 运行前成本预估 + 预算熔断 + 预算耗尽计入分母（暴露效率问题而非隐藏） |
| **能力分类争议** | 分解结果被质疑 | 分类法公开、标注依据留痕、争议可申诉并触发重标 |
