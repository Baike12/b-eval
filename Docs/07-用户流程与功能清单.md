# 07 · 用户流程与功能清单

## 7.1 核心用户旅程

### 旅程 A · Agent 开发者：接入并自测

```
① 注册被测对象（填名称、版本、接入方式）  →  ② 配置接入适配
        ↓
③ 跑接入自检（样例任务）  →  ④ 看自检结论：动作格式、契约违规、用量上报
        ↓                                    ↓ 不通过
⑤ 跑冒烟集（每域 ≤ 10 题）  →  ⑥ 确认基线分数入库  →  ⑦ 接入完成
```

**关键点：** 自检不通过时，评测功能对被测对象禁用——防止把接入 bug 记成能力差。

### 旅程 B · Agent 开发者：日常回归

```
① 发起评测（选任务集、选基线、选重复次数）
        ↓
② 看成本预估，确认预算  →  ③ 运行（可随时暂停/取消）
        ↓
④ 打开报告：先看可信度区（平台故障率、判定故障率）
        ↓
⑤ 定位变差的任务 →  下钻到轨迹 →  看失败模式归因
        ↓
⑥ 导出对比报告 / 提交内部评审
```

### 旅程 C · 任务作者：新增一道题

```
① 建草稿任务（填身份、能力标注、难度、场景域）
        ↓
② 写初始状态 + 交互契约（动作空间、观测、预算、终止条件）
        ↓
③ 写判分条件（选判分器、组合方式、参考解）
        ↓
④ 跑校验闸门（八项）  →  ⑤ 失败项逐条修
        ↓
⑥ 放入 dev 集合 →  ⑦ 用基线 Agent 跑一遍，看难度是否与标注一致
        ↓
⑧ 提交评审 →  ⑨ 通过后进入 test 集合并锁定版本
```

### 旅程 D · 评测组织者：批量评测与发布

```
① 建评测计划（多 Agent × 多任务集 × 重复次数）
        ↓
② 预估总成本，确认资源额度
        ↓
③ 运行（可中断续跑，实时看进度与故障率）
        ↓
④ 结果体检：平台故障率、判定故障率、饱和/污染提示
        ↓
⑤ 生成对比报告（多 Agent 横向、跨版本纵向）
        ↓
⑥ 提交榜单 →  平台重算 + 反作弊核验 →  ⑦ 公布或退回
```

### 旅程 E · 安全评审者：攻防评测

```
① 选用户任务集 + 攻击任务集
        ↓
② 配攻击策略 × 注入向量矩阵
        ↓
③ 选防御策略（可多个，形成对照组）
        ↓
④ 运行 →  ⑤ 看双轴报告：效用 / 定向 ASR / 非定向 ASR
        ↓
⑥ 对比不同防御的攻防权衡曲线 →  ⑦ 导出结论
```

### 7.3.2 交互原则

| 原则 | 具体表现 |
|---|---|
| **可信度前置** | 报告页顶部永远是可信度区（平台故障率、判定故障率、有效样本量），不允许折叠隐藏 |
| **异常显式** | 任何「被排除」「NA」「无覆盖」都必须在视觉上与正常值区分，且可点开看到原因 |
| **数字可下钻** | 每个汇总数字可点击进入构成它的 Trial 列表 |
| **差异化标注** | 同一个数字的不同聚合口径（macro/micro）并排展示并标注口径名，不允许只显示一个 |
| **同批次对比** | 同一任务集版本下的多次运行在同一页面并排，避免跨版本误比 |
| **失败可归因** | 失败任务默认展示归因结论，而不是只显示「失败」 |
| **显式覆盖** | 覆盖默认预算、并发、判分配置等行为时，必须显式操作并留痕 |

### 7.3.3 关键交互流程细节

**运行配置的成本预估反馈：** 修改重复次数、模型、任务集时，实时更新预估的 token / 费用 / 时长区间与置信度标注；预估不可靠时（历史样本不足）明确显示「预估置信度低」。

**暂停与取消：** 暂停保留已完成的 Trial；取消时区分「取消并保留已完成结果」与「取消并作废本次运行」，后者需二次确认。

**失败重试：** 报告中对失败 Trial 提供「仅重跑这些」操作，重跑作为新的 Trial 序号追加，不覆盖历史记录。

**离线重打分：** 对已完成的运行，用户可指定新判分器重新判定；界面明确提示「此操作不改写原结果，将产生新版本判定」，并支持两版本对比。

**改判：** 改判需填理由；理由为必填；改判后指标自动重算并提示「已重算」。

## 7.4 权限模型

| 角色 | 被测对象 | 任务（草稿/已发布） | 运行 | 判定与改判 | 榜单 |
|---|---|---|---|---|---|
| Agent 开发者 | 自己创建，可编辑 | 只读 | 可创建、可运行、可取消 | 只读 | 提交自己的成绩 |
| 任务作者 | 只读 | 草稿可编辑；已发布需申请修订 | 可运行自己的任务 | 只读 | 不可 |
| 基准维护者 | 只读 | 可发布/冻结/回滚 | 可运行 | 只读 | 可维护榜单 |
| 评测组织者 | 只读 | 只读 | 可创建、可暂停/取消、可重跑 | 只读 | 可提交、可发布 |
| 复核员 | 只读 | 只读 | 只读 | 可改判（留痕） | 只读 |
| 平台运营者 | 全部 | 全部 | 全部 | 全部 | 全部 |

**关键约束：** **任何人不得修改自己提交成绩对应的判定逻辑**。改判权与提交权分离，避免既当运动员又当裁判。
